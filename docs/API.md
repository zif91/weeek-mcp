## Общие принципы

Weeek MCP Server использует протокол JSON-RPC 2.0 для взаимодействия с клиентами. Все инструменты принимают параметры в виде JSON объекта и возвращают JSON ответ.

### Структура запроса

```json
{
  "jsonrpc": "2.0",
  "id": "request_id",
  "method": "run_tool",
  "params": {
    "name": "tool_name",
    "arguments": {
      "param1": "value1",
      "param2": "value2"
    }
  }
}
```

### Структура ответа

```json
{
  "jsonrpc": "2.0",
  "id": "request_id",
  "result": {
    "status": "success",
    "data": "..."
  }
}
```

## Аутентификация

Аутентификация происходит через API токен Weeek, который настраивается в файле конфигурации или через переменную окружения `WEEEK_API_TOKEN`.

## Форматы ответов

### Успешный ответ

```json
{
  "status": "success",
  "data": "...",
  "source": "api|cache",
  "total": 10
}
```

### Ответ с ошибкой

```json
{
  "status": "error",
  "error": "Описание ошибки",
  "code": 500,
  "details": "Дополнительная информация"
}
```

## Группы методов

### Управление задачами

#### `create_task`

Создает новую задачу в системе Weeek.

**Параметры:**
- `title` (string, обязательный) — Название задачи
- `description` (string, опционально) — Описание задачи
- `project_id` (string, опционально) — ID проекта
- `board_id` (string, опционально) — ID доски
- `board_column_id` (string, опционально) — ID колонки доски
- `parent_id` (string, опционально) — ID родительской задачи

**Пример запроса:**
```json
{
  "title": "Реализовать авторизацию",
  "description": "Добавить JWT авторизацию в API",
  "project_id": "123456",
  "board_id": "789012"
}
```

**Пример ответа:**
```json
{
  "status": "success",
  "task": {
    "id": "654321",
    "title": "Реализовать авторизацию",
    "description": "Добавить JWT авторизацию в API",
    "project_id": "123456",
    "board_id": "789012",
    "board_column_id": null
  }
}
```

#### `get_tasks`

Получает список задач с возможностью фильтрации.

**Параметры:**
- `project_id` (string, опционально) — Фильтр по проекту
- `board_id` (string, опционально) — Фильтр по доске
- `board_column_id` (string, опционально) — Фильтр по колонке доски

**Пример ответа:**
```json
{
  "status": "success",
  "source": "cache",
  "total": 5,
  "tasks": [
    {
      "id": "654321",
      "title": "Реализовать авторизацию",
      "description": "Добавить JWT авторизацию в API",
      "is_completed": false,
      "project_id": "123456",
      "board_id": "789012",
      "board_column_id": "111",
      "tags": []
    }
  ]
}
```

#### `get_task`

Получает информацию о конкретной задаче.

**Параметры:**
- `task_id` (string, обязательный) — ID задачи

#### `update_task`

Обновляет существующую задачу.

**Параметры:**
- `task_id` (string, обязательный) — ID задачи
- `title` (string, опционально) — Новое название
- `description` (string, опционально) — Новое описание

#### `complete_task`

Отмечает задачу как выполненную.

**Параметры:**
- `task_id` (string, обязательный) — ID задачи

#### `uncomplete_task`

Снимает отметку выполнения с задачи.

**Параметры:**
- `task_id` (string, обязательный) — ID задачи

#### `delete_task`

Удаляет задачу.

**Параметры:**
- `task_id` (string, обязательный) — ID задачи

#### `update_task_board`

Перемещает задачу на другую доску.

**Параметры:**
- `task_id` (string, обязательный) — ID задачи
- `board_id` (string, обязательный) — ID новой доски

#### `update_task_board_column`

Перемещает задачу в другую колонку доски.

**Параметры:**
- `task_id` (string, обязательный) — ID задачи
- `board_column_id` (string, обязательный) — ID колонки
- `upper_task_id` (string, опционально) — ID задачи, над которой разместить

### Учет времени

#### `add_task_time_entry`

Добавляет запись учета времени к задаче.

**Параметры:**
- `task_id` (string, обязательный) — ID задачи
- `user_id` (string, обязательный) — ID пользователя
- `date` (string, обязательный) — Дата в формате YYYY-MM-DD
- `duration` (number, обязательный) — Продолжительность в минутах
- `comment` (string, опционально) — Комментарий
- `is_overtime` (boolean, опционально) — Признак сверхурочной работы

**Пример запроса:**
```json
{
  "task_id": "654321",
  "user_id": "999",
  "date": "2023-12-15",
  "duration": 120,
  "comment": "Работа над авторизацией",
  "is_overtime": false
}
```

## Кэширование

Система использует файловое кэширование для ускорения работы. Кэш хранится в папке `cache/` и включает:

- `projects.json` — Кэш проектов
- `boards.json` — Кэш досок
- `board_columns.json` — Кэш колонок досок
- `tasks.json` — Кэш задач
- `tags.json` — Кэш тегов

### Управление кэшем

Кэш автоматически обновляется при:
- Создании новых сущностей
- Обновлении существующих сущностей
- Удалении сущностей

Также доступны методы принудительного обновления:
- `reload_boards_cache` — Обновление кэша досок

### Структура кэша

```json
{
  "lastUpdated": 1702648200,
  "data": [
    {
      "id": "123",
      "title": "Название",
      "...": "другие поля"
    }
  ]
}
```

## Обработка ошибок

### Коды ошибок

- `400` — Неверные параметры запроса
- `404` — Сущность не найдена
- `500` — Внутренняя ошибка сервера
- `401` — Ошибка аутентификации
- `403` — Нет прав доступа

### Типичные ошибки

1. **Отсутствие обязательных параметров**
```json
{
  "status": "error",
  "error": "Не указано название задачи",
  "code": 400
}
```

2. **Сущность не найдена**
```json
{
  "status": "error",
  "error": "Задача не найдена",
  "code": 404
}
```

3. **Ошибка API Weeek**
```json
{
  "status": "error",
  "error": "API Error: Invalid token",
  "code": 401,
  "details": {
    "api_response": "..."
  }
}
```

## Логирование

Система ведет подробные логи:

- **Входящие запросы** — Все MCP запросы логируются с параметрами
- **API вызовы** — Все обращения к Weeek API логируются
- **Операции кэша** — Обновления кэша логируются
- **Ошибки** — Все ошибки логируются с трассировкой стека

Логи записываются в `STDERR` и в файлы `server_log.txt` и `client_log.txt`.

```json
{
  "auth": {

  "default_board_id": "789012", 
  "default_user_id": "999",
  "timezone": "Europe/Moscow",
  "update_cache_after_create": true

```

### Переменные окружения

- `WEEEK_API_TOKEN` — API токен Weeek
- `WEEEK_PROJECT_ID` — ID проекта по умолчанию
- `WEEEK_BOARD_ID` — ID доски по умолчанию
- `WEEEK_USER_ID` — ID пользователя по умолчанию
- `DEBUG` — Включение отладочного режима

## Архитектура

### Основные классы

- `WeeekMcp` — Основной класс MCP сервера
- `TaskManager` — Управление задачами
- `Cache` — Система кэширования (Singleton)
- `CacheLoader` — Загрузка данных в кэш
- `MpcReader` / `MpcWriter` — Чтение/запись MCP сообщений

### Поток данных

1. Клиент отправляет MCP запрос
2. Сервер парсит запрос и определяет инструмент
3. Инструмент выполняет бизнес-логику
4. При необходимости происходит обращение к Weeek API
5. Результат кэшируется (если применимо)
6. Ответ отправляется клиенту

### Обработка ошибок

Система имеет многоуровневую обработку ошибок:

1. **Уровень MCP** — Ошибки протокола
2. **Уровень инструментов** — Валидация параметров
3. **Уровень API** — Ошибки Weeek API
4. **Уровень кэша** — Ошибки файловой системы

Все ошибки логируются и возвращаются в стандартизированном формате.
